Naganoor Village App — setup
============================

1) Install Flutter and run:
   flutter pub get

2) Supabase configuration (local, not committed):
   - Copy dart_defines.example.json to dart_defines.json
   - Fill in SUPABASE_URL and SUPABASE_ANON_KEY
   - dart_defines.json is gitignored — do not commit real keys

3) Run on Chrome with Supabase:
   flutter run -d chrome --dart-define-from-file=dart_defines.json

   Or:
   .\scripts\run_chrome.ps1

4) Apply database schema (first time only):
   Supabase Dashboard → SQL Editor → run supabase/schema.sql
   Then run supabase/apply_village_app_users.sql (required for signup / users)
   Then run supabase/migrations/20250523_hybrid_auth.sql (password admin fields)

6b) Auth (hybrid):
   - Village users: /signup — one-time Email OTP, permanent session
   - Super admin: /admin/login — ravivtu12345@gmail.com + SUPER_ADMIN_PASSWORD
   - Dept admins: super admin creates with temp password → approve →
     /admin/login (password) → one-time OTP at /admin/activate → password only

   If signup shows "Could not find table village_app_users", paste and run
   apply_village_app_users.sql, then hot-restart the app.

5) Create an admin user:
   - Dashboard → Authentication → Users → Add user
   - SQL Editor:
     update public.users set role = 'admin' where email = 'your-admin@email.com';

6) Admin sign-in in the app:
   News tab → shield icon → email + password

7) Optional Maps:
   Add MAPS_API_KEY to dart_defines.json

Environment keys (dart_defines.json):
- SUPABASE_URL
- SUPABASE_ANON_KEY
- MAPS_API_KEY (optional)

8) Auto-update when you push to GitHub (main branch)
   The repo includes GitHub Actions workflows:

   a) .github/workflows/ci.yml
      - Runs flutter analyze + flutter test on every push/PR to main.

   b) .github/workflows/deploy-android.yml
      - On push to main: bumps build number, builds signed AAB + APK,
        uploads to Google Play (internal track by default), commits
        pubspec version back to git.
      - Phones installed from Play (same track) see an in-app update
        prompt on next open (AppUpdateHost + in_app_update package).

   c) .github/workflows/deploy-web.yml
      - On push to main: builds web and deploys to GitHub Pages
        (users get latest on browser refresh).

   One-time GitHub secrets (Settings → Secrets and variables → Actions):
   - SUPABASE_URL, SUPABASE_ANON_KEY
   - ANDROID_KEYSTORE_BASE64 (base64 of your .jks file)
   - ANDROID_KEYSTORE_PASSWORD, ANDROID_KEY_ALIAS, ANDROID_KEY_PASSWORD
   - GOOGLE_PLAY_SERVICE_ACCOUNT (Play Console API JSON)

   Optional repository variable (Settings → Variables):
   - PLAY_TRACK = internal | alpha | beta | production

   Play Console: add testers to the same track CI uses (default: internal).
   Sideload APKs do NOT auto-update via Play — use Play internal testing
   or download the APK from the GitHub Actions artifact after each deploy.

   Manual deploy: GitHub → Actions → Deploy Android → Run workflow.
